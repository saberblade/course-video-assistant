# 03 新机冷启动部署手册

**目的**：在任何一台"裸"Windows 11 机器上，仅凭 **GitHub 仓库 + 本手册** 把系统从零跑到 `http://127.0.0.1:8000` 全链路可用——这是 M4「冷启动验收」的执行依据，也是"只在一台机好好的"问题的解药。

**验收口径**：全部命令在目标机上真实执行并留证据（截图/文本），不做"应该没问题"推断；实测值回填 docs/environment-versions.md 对应行或本文末模板。

**记录口径（2026-11-09 基准机实测）**：CPython 3.11.0；ffmpeg/ffprobe 6.1.1（gyan.dev essentials）；faster-whisper 1.2.1；model.bin 483,546,902 B，sha256=3e3059…70d671；requirements.lock.txt 44 包，sha256=65c7f7…2921d。

---

## 0. 路径选择

| | 路径 A：快车道（推荐，约 30 分钟） | 路径 B：纯网络自举（约 60–90 分钟） |
| --- | --- | --- |
| 前提 | 手边有一台**已就绪的 SYS 机** + U 盘/局域网 | 只有仓库和公网 |
| 大件来源 | model.bin（483MB）、tools\ffmpeg、frontend\dist 直接拷贝 | 自行下载（清华 pip 源 / npmmirror / hf-mirror） |
| 适用 | 中午联调、演示 | 正式 M4 冷启动验收（更严格、更可信） |

两条路径的第 1 步（取代码）和第 6 步（配置+启动）**完全相同**。

---

## 1. 取代码（两路径共用）

```powershell
git clone https://github.com/saberblade/course-video-assistant.git D:\cva
cd D:\cva
git log --oneline -1   # 记录本次部署基于的 commit 哈希，写入验收记录
```

- 大陆直连不稳：`git ls-remote` 小请求通常可通，clone 大流量易断——开代理后执行 `git -c http.proxy=http://127.0.0.1:7897 clone …`（端口按本机代理软件实际值）。
- 无 git 的机器：下载 zip 解压亦可，但验收记录须注明"非 git 拉取、无 commit 锚点"。

## 2. Python 3.11

```powershell
# 安装 CPython 3.11.x（python.org 官方安装包，勾选 "Add to PATH" 或记录绝对路径）
py -3.11 --version          # 期望: Python 3.11.0（3.11.x 均可，写实测值）
cd D:\cva
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe --version
```

## 3. 后端依赖（回到项目根）

在线（清华源，快）：
```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```
离线（更稳，先在来源机执行下载到 wheels\ 目录再整目录拷贝）：
```powershell
# —— 来源机 ——
.\.venv\Scripts\python.exe -m pip download -r requirements.lock.txt -d wheels -i https://pypi.tuna.tsinghua.edu.cn/simple
# —— 目标机 ——
.\.venv\Scripts\python.exe -m pip install --no-index --find-links wheels -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip freeze > logs\pip_freeze_newmachine.txt   # 留证据
```
锁文件校验（可选）：
```powershell
Get-FileHash requirements.lock.txt -Algorithm SHA256   # 期望 65C7F7A0CC1C710AD52406899CCB1F33DFD784145DA9F4922F298A3E752921D
```

## 4. FFmpeg 6.1.1

- 路径 A：拷贝来源机 `tools\ffmpeg\` 整目录（ffmpeg.exe + ffprobe.exe）。
- 路径 B：npmmirror/gyan.dev 下载 6.1.1 essentials，解压到 `tools\ffmpeg\`。
- 验证：
```powershell
tools\ffmpeg\ffmpeg.exe -version | Select-Object -First 1   # 期望 ffmpeg version 6.1.1 ...
```

## 5. 转写模型 483MB

**首选**：U 盘拷来源机 `models\faster-whisper-small\`（model.bin 等 5 个文件），目标机校验：
```powershell
(Get-FileHash models\faster-whisper-small\model.bin -Algorithm SHA256).Hash
# 期望 3E305921506D8872816023E4C273E75D2419FB89B24DA97B4FE7BCE14170D671
```
**无 U 盘**：直接跑自带的多线程下载器（16 路断点续传 + 自动 sha256 校验，走 hf-mirror）：
```powershell
.\.venv\Scripts\python.exe scripts\download_model_bin.py
# 结尾应打印 RESULT: PASS
```

## 6. 前端构建产物

- 路径 A：拷来源机 `frontend\dist\`（8 个文件，1,670,883 B）。
- 路径 B：装 Node 22.x（≥22.12；建议用来源机 tools\node22\ 便携版，避免全局 Node 冲突），然后：
```powershell
cd frontend
..\tools\node22\npm.cmd ci     # npm ci 只按 package-lock 装，不升级版本
..\tools\node22\npm.cmd run build   # 产物 frontend\dist\；chunk>500kB 告警属正常
cd ..
```

## 7. 服务端配置 .env.local（密钥唯一落点）

在仓库根新建 `.env.local`，模板如下——**两个路径要改**：`FFMPEG_BIN`/`FFPROBE_BIN` 改成目标机实际绝对路径；`LLM_API_KEY` 由 SYS/PM **现场填入**（密钥不进 git、不进聊天记录、不进任何文档）：

```ini
APP_ENV=demo
APP_HOST=127.0.0.1
APP_PORT=8000
DATA_DIR=./data
FFMPEG_BIN=<目标机仓库绝对路径>\tools\ffmpeg\ffmpeg.exe
FFPROBE_BIN=<目标机仓库绝对路径>\tools\ffmpeg\ffprobe.exe
WHISPER_MODEL_DIR=./models/faster-whisper-small
WHISPER_DEVICE=cpu
WHISPER_COMPUTE_TYPE=int8
WHISPER_LANGUAGE=zh
MAX_UPLOAD_BYTES=209715200
MAX_VIDEO_SECONDS=1200
MAX_UNFINISHED_JOBS=3
TRANSCRIBE_CONCURRENCY=1
TASK_TIMEOUT_SECONDS=1200
TASK_EXECUTOR_ENABLED=1
QUESTION_CONCURRENCY=1
RETRIEVAL_TOP_K=5
MAX_CONTEXT_CHARACTERS=6000
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=<现场填入，sk- 开头>
LLM_MODEL=qwen-plus
LLM_CONNECT_TIMEOUT_SECONDS=5
LLM_TOTAL_DEADLINE_SECONDS=25
ANSWER_MODE=generative
```

无密钥也能启动与跑 extractive 路径（`llm_configured=false`，问答降级），验收生成式需要有 key。

## 8. 启动 · 停止 · 验证

```powershell
powershell -ExecutionPolicy Bypass -File deploy\start.ps1
# 脚本自检 venv/.env.local/模型，缺什么会明确报错；前台运行，Ctrl+C 停止
# （新开控制台跑: add -NewConsole）
```
健康验证（另开一个 PowerShell）：
```powershell
Invoke-WebRequest http://127.0.0.1:8000/api/health -UseBasicParsing -TimeoutSec 5 | % Content
# 期望: {"status":"ok",...,"transcriber":"ready","llm_configured":true}
```
浏览器打开 `http://127.0.0.1:8000` 应见前端 UI。停止：`deploy\stop.ps1`。

> 冷启动口径：`start.ps1` 从**服务未运行**状态拉起到 health 200 为冷启动；用秒表记录耗时入验收记录。

## 9. 冒烟（两选一，留证据）

**自动化**（密钥感知断言；结果写入 logs/e2e_local_run.json）：
```powershell
.\.venv\Scripts\python.exe scripts\e2e_smoke.py
# 注意: 脚本 pre_clean 会删除库中全部视频——正式演示数据先备份或先跑 backup.ps1
```
**手动 UI**：上传一段 ≤200MiB/≤1200s 的 H.264/AAC MP4 → 等 ready → 提问看引用 → 删除。无样本时先 `powershell -ExecutionPolicy Bypass -File scripts\make_sample_video.ps1` 生成 TTS 样本（约 117 秒）。

## 10. 新机已知坑速查

| 现象 | 原因/解法 |
| --- | --- |
| PowerShell 控制台中文乱码 | PS5.1 GBK 显示问题，以文件内容（UTF-8）为准 |
| clone 卡死/断流 | 大陆直连不稳，开代理 `-c http.proxy=…`；zip 兜底 |
| 端口 8000 被占 | 先 `deploy\stop.ps1`；脚本自带占用保护 |
| urllib 超时参数报错 | timeout 只接受单个数值（连接/读共用） |
| robocopy 拷单文件失败 | robocopy 不支持单文件目标，用 Copy-Item |
| pip 装包很慢 | 用清华源；faster-whisper 链路含 onnxruntime 大包 |
| hf-mirror 单线程极慢 | 用 `scripts/download_model_bin.py`（并发+断点续传） |
| key 报 403 access_denied | 新 key 用默认业务空间、不设 IP 白名单 |
