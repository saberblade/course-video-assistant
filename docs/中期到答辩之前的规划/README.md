## 先回答三个问题

**后端数据库。** 当前SQLite已保存视频信息、转写、章节和提交过的课程问答。复习标记、备注尚在浏览器localStorage，播放位置没有服务端档案，历史问答也缺少读取接口。本阶段把这些学习记录迁到后端，与账号绑定。

**你看到的快速回答，有两种来源。** 悬浮助教的本机`VITE_ASSISTANT_USE_API=false`，当前用预设站内指引；视频页“向课程提问”已调用后端模型，实测约3秒。回答快不能单独证明是假调用，界面应清楚展示生成/检索/指引的实际状态，不人为增加延迟。

**已经有基础RAG。** 当前代码先用BM25找本视频原文，再把候选交给模型生成，最后核对引用。本阶段增强为“BM25＋语义向量混合检索、时间戳可追溯、按账号隔离”。RAG本身是已有技术，适合把本项目的场景设计和验证结果作为工程创新点。

## 本轮目标顺序

1. M1必达：注册/登录/退出；私有课程隔离；后端保存播放位置、复习标记和备注；问答历史刷新可恢复。
2. M2并行研发：混合检索RAG，保留真实引用、时间定位和无依据拒答，做同题集对照。
3. M3收口：跨浏览器保存、双账号隔离、异常恢复、数据库迁移与备份验收。RAG未验证出效果时保留基础BM25链路，不宣称提升。

继续使用FastAPI、SQLAlchemy、SQLite、Vue、faster-whisper和qwen-plus。新增数据库迁移、密码哈希与语义向量适配；本阶段不另建MySQL、Redis或独立向量服务。
