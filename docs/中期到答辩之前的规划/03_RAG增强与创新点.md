# RAG增强与创新点

## 已有与新增

按当前源码推断，项目已经具备基础检索增强生成结构：`retrieval.py`用BM25检索当前视频原文，`qa.py`将候选交给模型，引用再从数据库回填。这属于已有实现，不应重新包装成“下一阶段首次实现RAG”。[RAG原始论文](https://arxiv.org/abs/2005.11401)可作为技术背景。

本轮新增目标是：**账号隔离的课程私域混合检索＋可追溯时间戳引用＋可恢复的复习档案**。这是场景与工程特色，不能宣称发明RAG，也不能在未做对照时宣称准确率提升。

## 推荐实施

| 部分 | 方案 / 负责人 |
| --- | --- |
| 原文与块 | 卢乙源实现构建逻辑；合并相邻完整转写，目标约120—240字、尽量不跨30秒，长片段不伪造拆分时间；保留segment_ids和真实区间。chunking_version固定 |
| 关键词检索 | 保留BM25；在同一批块上建立对照基线，不删除现有已可运行链路 |
| 语义向量 | 百炼`text-embedding-v4`，1024维；文档见[向量接口](https://help.aliyun.com/en/model-studio/text-embedding-synchronous-api) |
| 持久化 | SQLite存块、模型/维度/文本哈希、float32向量和索引状态；NumPy计算余弦相似度，适用于本轮少量课程 |
| 融合 | BM25与向量结果各取候选，按块ID去重，用RRF融合；初始k=60，保留最终top5和总上下文6000字符上限 |
| 生成与引用 | 继续qwen-plus；许梓轩接入既有课程问答API，严格校验has_evidence与引用ID，后端回填原文和时间 |
| 失败处理 | 向量接口故障/索引未就绪时明确回BM25；生成故障单独按既有degraded规则处理 |

RRF合并的是排名，不把BM25原始分数直接加到余弦分数上；参考[官方RRF说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)。公式为各路`1/(60+rank)`之和，rank从1开始。融合分数不是“回答可信度百分比”。本方案只复用这一算法，不引入Elasticsearch服务。

11月11日已对现有账户做一次极小向量接口探测，HTTP200、返回1024维，用时1.16秒。见[连通证据](向量API连通证据.json)。这只证明接口可用，不代表向量入库、混合检索或评测已经实现。所有模型密钥仍只留在服务器配置。

## 模块与索引生命周期

卢乙源主改`modules/retriever/`，提供类型化的块、候选与检索结果接口。许梓轩先执行身份和视频归属检查，再调用模块；李沛丰维护对应迁移和持久化约定。不得把未授权的全库原文送去embedding或LLM后才过滤。

新视频处理完成后创建索引任务，后台构建并持久登记状态。课程内容ready与向量索引ready分开；向量失败不应让原本可用的基础视频复习消失。查询只读当前attempt、text_hash、chunking_version及模型/维度一致的有效向量。

更新或重试必须使旧索引失效；删除视频清理块、向量和缓存；服务重启可从持久任务状态重建，不依赖仅在内存的向量表。超时、限流、维度不符、空向量和范数为0都要受控处理，不能让问题变500或产生假引用。

保留`retrieval_mode=bm25/hybrid/bm25_fallback`，与回答的generative/extractive分开。诊断信息给开发和QA，学生页面重点展示回答、原文依据、回看和必要降级提示，不让学生配置向量算法。

## 如何证明有用

李沛丰主导评测，卢乙源提供检索追踪，许梓轩提供可固定版本的生成入口。

1. 固定三段正式授权录课、20道有依据题和5道无依据题；20题中包含同义改写题，标注正确原文片段。不能看结果后临时删难题。
2. 先做离线检索：A为原60秒BM25；B为新块BM25；C为同一批新块上的BM25＋向量RRF。B与C的比较才用于判断语义融合的增益，避免把分块变化混成“向量提升”。
3. 主要记录Hit@1和MRR：第一名是否包含支持片段，首个支持块排名的倒数。top5如果覆盖了几乎全部候选，不用Hit@5美化结果。
4. 生成式回答比较B和C时，使用同一模型、提示词、问题、判题规则和上下文上限；按既定正题/拒答/引用指标登记。人工评审最好不先看方法标签。
5. 向量请求缓存命中与首次调用分开记录；离线缓存评测不冒充线上实时耗时。输出延迟、调用次数、失败与降级数。先少量样本和固定题集，不全库盲目调用。

目标是查明同义改写召回是否改善，同时保持拒答、引用合法和权限隔离。若混合检索无收益或回归，保留BM25为默认，记录实际结果；不能伪造提升百分比。

## 可用于答辩的表述

实现并验收后可表述：

> 面向中文课程复习，将关键词与语义检索结合，回答可回溯到原文和视频时间点；复习位置、标记和疑问随账号保存，形成“提问—核对—回看—记录”的闭环。

未验收前，以上是目标描述。具体提升幅度只能引用评测记录；RAG不能自动修复所有转写错误，也不能等同于自动判断学生掌握程度。
