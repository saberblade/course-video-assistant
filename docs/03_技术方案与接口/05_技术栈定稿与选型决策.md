# 首版技术栈定稿与选型决策

版本V1.1。决策日期2026年11月5日。决策负责人：PM兼组长。工程执行负责人：SYS，协作FE与BE，验证QA。

## 已完成的决定

课程视频复习助手首版采用Vue前端、Python FastAPI后端、SQLite与本地文件、faster-whisper本地语音转写、BM25原文检索、百炼通义千问API生成回答。下面列出的框架、模型、部署方式和岗位边界已定稿，四位成员可直接按此开工，不再把选技术栈当作待讨论任务。

“技术选型已定稿”与“依赖已安装验证”是两件事。本次完成的是前者及工程交接规范；目标电脑安装、补丁版本锁定、真实转写与API连通由SYS组织FE/BE在M1前完成并提交证据。当前没有实机运行记录，不能写成环境已经验证。

## 固定技术组合

| 层次 | 首版决定 | 实现主责 | 执行约束 |
| --- | --- | --- | --- |
| 前端运行环境 | Node.js 22 LTS线，版本不低于22.12 | SYS准备，FE使用 | 不使用Node 18或22.0等不满足Vite 7要求的版本 |
| 页面框架 | Vue 3与TypeScript 5 | FE | 两个主页面，代码和接口类型同步 |
| 构建与组件 | Vite 7、Element Plus 2 | FE | 沿用本主版本线，首次构建后锁定精确依赖，不在开发中临时换框架 |
| 请求与播放器 | Axios 1、HTML5 video | FE | 接口走/api；播放器支持引用秒数定位，不额外引入播放器框架 |
| 后端运行环境 | Python 3.11独立虚拟环境 | SYS准备，BE使用 | 不混用系统全局包或多个Python小版本 |
| 服务与数据校验 | FastAPI 0.x（≥0.128）、Pydantic 2、Uvicorn单worker | BE | 使用Pydantic v2模型；音频任务不阻塞请求事件循环 |
| 数据访问与存储 | SQLAlchemy 2、SQLite、本地文件目录 | BE | SQLite存元数据与任务，视频和派生文件按UUID存本地 |
| 上传 | python-multipart | BE | file字段，服务端独立验证文件，不用JSON传base64 |
| 音视频工具 | FFmpeg、ffprobe | SYS | 独立命令用于媒体探测及约定音轨处理，由SYS记录完整版本和路径 |
| 语音模型 | faster-whisper，多语言small，CPU，int8 | SYS | 模型在本地models/faster-whisper-small目录加载；不以GPU作为前置 |
| 原文检索 | jieba、rank-bm25 | BE | 仅检索当前视频，top_k=5；不把分数当概率 |
| 大模型 | 百炼通义千问qwen-plus | BE接入，SYS配账户 | 模型名固定，使用httpx调用OpenAI兼容HTTP接口；端点从账户控制台配置 |
| 交付运行 | Windows本机，127.0.0.1:8000，FastAPI同源托管前端build | SYS | 单个Uvicorn worker；开发期可用Vite代理，验收使用打包版本 |
| 测试工具 | pytest用于后端自动化，浏览器与人工语义核验 | QA，BE协作 | pytest只执行适合自动化的断言；答案是否被原文支持仍由QA核验 |

没有指定主版本号的Python库，名称已固定；SYS在上述Python与后端组合内解析兼容版本并记录精确版本。发布验收以锁文件实际内容为准，不以宽泛版本范围代替可复现环境。

Vite 7文档要求Node 20.19+或22.12+，本项目固定选择22线且至少22.12；FastAPI官方说明较新版本使用Pydantic v2，本项目直接采用Pydantic 2，不维护v1兼容模型。[Vite 7官方文档](https://v7.vite.dev/guide/)、[FastAPI迁移文档](https://fastapi.tiangolo.com/how-to/migrate-from-pydantic-v1-to-pydantic-v2/)

faster-whisper本身可通过PyAV解码，不要求单独安装系统FFmpeg。本项目仍明确安装FFmpeg/ffprobe，用于服务端输入验证和统一音轨处理；这是项目决策，不是对该库前提条件的误述。[faster-whisper官方说明](https://github.com/SYSTRAN/faster-whisper)

## 选型决策记录

| 决策ID | 决定与理由 | 本轮舍弃 | 代价与边界 |
| --- | --- | --- | --- |
| ADR-01 | Vue 3加组件库实现上传、列表与复习页，减少重复写基础控件 | 同时维护React版或桌面PyQt版 | 首版按现代浏览器与本机Web应用交付 |
| ADR-02 | Python统一承载接口、检索和模型模块，FastAPI明确数据协议 | 再加Java/Node业务后端 | 转写在独立进程顺序运行，BE需保证接口不被计算阻塞 |
| ADR-03 | SQLite和本地文件满足小组单机交付，减少服务数量 | MySQL/PostgreSQL、对象存储、向量数据库 | 不承诺生产级并发、账号隔离或多台服务器共享数据 |
| ADR-04 | small多语言模型加CPU int8，避免GPU环境成为必经依赖 | large模型、CUDA优化和自行训练基础模型 | 中文术语准确率与处理耗时必须真实测量 |
| ADR-05 | BM25结合中文分词，先交付可追溯的课程检索 | 首版向量嵌入、混合检索、多检索器融合、LangChain | 同义表达可能漏召回，需要独立题库评估，不宣传完整语义理解 |
| ADR-06 | qwen-plus经兼容HTTP协议生成答案，SDK层保持简单 | 同时接入多家模型、自建LLM服务 | 依赖账户权限、网络和费用，失效时明确降级为原文检索 |
| ADR-07 | SQLite持久队列、转写并发1、问答生成并发1、Uvicorn单worker | Redis、Celery和多worker部署 | 排队容量3，超限拒绝；避免多进程重复加载模型或领取任务 |
| ADR-08 | Windows本地脚本加前端build为必达交付 | 本轮Docker、云端部署、公共互联网服务 | M4必须实机启动和恢复验证，展示和彩排暂缓 |

选用某个框架是组长作出的实施决定，不代表它在任何场景都最好。决策围绕五个核心开发日、四位工程成员和单机课程复习范围，不把比较意见当作实测性能结论。

## 四岗模块边界

- FE拥有frontend，负责页面、状态、接口类型、播放器及当前页面会话的问答显示。刷新不恢复历史UI，不新增历史问答API需求。
- BE拥有backend/app及检索/问答业务，负责接口、数据库、队列状态、约60秒检索块、固定章节提要、模型调用、引用校验、重试和删除。
- SYS拥有modules/transcriber、环境准备和scripts运行交付，负责FFmpeg/ffprobe、模型文件、转写子进程、取消超时、依赖整合与数据备份恢复。
- QA拥有测试用例、人工标注、缺陷与证据，负责验证实际行为。不能因为响应200或引用ID存在就判答案正确。

SYS不写业务SQLite状态，BE不把模型下载、音频环境和进程清理全部退回自己处理。模块交接按[API与模型契约](02_API与数据模型契约.md)执行，不以“交给后端自行看着接”代替明确输入输出。

## 跨模块固定口径

1. transcribe(video_path, output_dir)返回TranscriptSegment列表，片段字段为id、start_sec、end_sec、text。Citation使用segment_id，它等于对应TranscriptSegment.id，由BE回填原文与时间。
2. Video上传响应的ID字段为id，FE从该字段取值用于后续路径video_id；不是从上传响应读取不存在的video_id字段。
3. 章节按固定60秒窗口聚合，标题为“mm:ss 章节提要”，正文按时间摘取原句至最多120字符，保留完整来源ID。空窗口跳过，不调用大模型编写章节内容。
4. queued阶段等待时间独立显示：首次按created_at，retry重新入队按updated_at；开始处理后使用elapsed_sec。性能指标排除上传与排队，另报用户总等待。
5. 问答分answered/generative、not_found/extractive、degraded/extractive。模型故障不等于课程没有答案；降级不能计入正式生成通过率。
6. 小组所有成员使用[接口Mock](04_接口Mock示例.json)的同一结构。Mock是虚构联调样例，不能作为语音模型输出或验收数据。

## 锁文件和版本记录的完成标准

requirements.lock.txt需包含安装环境内后端及转写全部精确依赖版本，不能只有fastapi等浮动包名；FE提交与package.json匹配的package-lock.json。SYS在docs/environment-versions.md记录操作系统、Python完整版本、Node完整版本、FFmpeg/ffprobe版本与路径、faster-whisper/CTranslate2版本、small模型目录与可校验来源、实际qwen-plus端点地区和验证日期。禁止记录密钥。

首次本机通过后应在另一独立环境执行npm ci和pip按锁文件安装，再验证health、转写、问答与播放器Range。不是要求多台机器必须同时在场；有一台电脑时用全新目录和全新虚拟环境验证。未获得这些证据前，只能标“选型已定，环境验证待执行”，不能标“可复现已通过”。

## 技术变更规则

以下情形才提出变更：真实安装不兼容且无法在既定版本线修复；账户无法使用qwen-plus；small在目标设备经排查仍不能满足可接受的质量或耗时；必要依赖出现必须处理的问题。

变更发起人须提交事实证据、现有版本、最小替代方案、受影响需求/接口/测试和预计工作量。SYS负责环境方案，BE负责接口与模型适配影响，FE负责界面影响，QA负责复测范围，PM记录是否采纳。改模型或检索策略后重跑同一正式验收集，不能沿用旧结果。

日常密钥轮换、账户地区端点填入和按既定主版本线首次锁补丁，属于SYS执行配置与验证，不属于重新选择技术栈。不得因为个人偏好改用React、换数据库、加入向量库或另接一种模型。
