# 迁移、备份与维护

## 一、数据库迁移（Alembic）

迁移链：

| 版本 | 内容 |
| --- | --- |
| `20261112_0001` | 基线：users / sessions / videos（含 owner_id）/ segments / chapters / questions |
| `20261112_0002` | 学习档案与 RAG：playback_progress、review_records、rag_indexes、rag_chunks、chunk_embeddings，questions 增补检索元数据 |

```powershell
# 升级到最新（启动脚本已自动执行这一步）
.\.venv\Scripts\python.exe -m alembic upgrade head

# 查看当前版本 / 历史
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic history

# 在副本上演练（不碰正式库）
.\.venv\Scripts\python.exe -m alembic -x db_url=sqlite:///backups/rehearsal.db upgrade head
```

**旧库兼容**：`migrations/env.py` 检测到「有 videos 表但没有 alembic_version」时，会先把版本标记到基线再跑增量，
不删库、不重建。已实测：4 个视频 / 817 分段 / 31 章节 / 13 问答在升级前后行数一致。

注意：`alembic.ini` 必须保持纯 ASCII。configparser 在中文 Windows 上按 GBK 读取，文件里有中文注释会直接报
`UnicodeDecodeError`。

## 二、备份与恢复

```powershell
# 备份（服务必须先停；脚本检测到端口在监听会拒绝执行）
powershell -ExecutionPolicy Bypass -File deploy\stop.ps1
powershell -ExecutionPolicy Bypass -File deploy\backup.ps1 -Keep 7

# 恢复（同样要求服务已停）
powershell -ExecutionPolicy Bypass -File deploy\restore.ps1 backups\20261112_134349
```

备份使用配置与环境变量解析后的真实 `DATA_DIR`，包含数据库、媒体、档案与向量，以及源码、迁移链、依赖锁和 `frontend/dist`。新版快照提供 `manifest.json` 全文件清单与 SHA-256，保留 `MANIFEST.txt` 作为入口。模型与工具版本见本目录的资源清单。

不备份 `.venv`、`node_modules`、`tools/`、`models/`、`.env.local`。恢复前需停止服务；先校验文件清单、哈希、数据库完整性和外键，再从暂存目录整体切换，避免混入备份后新增文件。原数据和构建保留为同父目录的 `*.pre_restore_*`，失败自动回滚；这些副本不参与快照轮转。

恢复到不同 DATA_DIR 时自动重定位媒体路径；配置与口令文件不被覆盖。独立干净目录恢复已实测：登录、媒体 Range、续播、备注、历史和向量可读，见[本轮证据](../../tests/evidence/final_runtime_20261112.json)。旧备份若只有 MANIFEST.txt，新版不会直接覆盖现库，需在隔离目录核对并转换。

迁移前的手工恢复点也保留在 `backups/app.db.pre_alembic_*.bak`。

**恢复后必须核对**：`/api/health` 为 ok、能登录、能播放、能续播、能看到备注与历史、`alembic current` 与备份时一致。

## 三、账号与数据维护

```powershell
# 只读检查：账号数、未归属视频、孤儿会话、重复标记、媒体缺失、索引状态
.\.venv\Scripts\python.exe scripts\maintain_accounts.py check

# 列账号 / 列未归属视频
.\.venv\Scripts\python.exe scripts\maintain_accounts.py list-users
.\.venv\Scripts\python.exe scripts\maintain_accounts.py unowned

# 创建演示账号（密码交互输入，不回显、不写日志）
.\.venv\Scripts\python.exe scripts\maintain_accounts.py create-user --username demo_a --display-name 演示甲

# 重置密码并撤销该账号所有会话
.\.venv\Scripts\python.exe scripts\maintain_accounts.py reset-password --username demo_a

# 把未归属的旧视频认领给指定账号（已归属会被拒绝，不会覆盖）
.\.venv\Scripts\python.exe scripts\maintain_accounts.py claim-video --video-id <UUID> --username demo_a
```

所有写操作先打印「将改哪个账号 / 哪个视频」，再要求输入 `yes`；`--yes` 仅用于脚本化演示。
密码只走交互输入或 `--password-stdin`，不接受命令行明文参数。

## 四、RAG 索引维护

```powershell
# 查看每个视频的索引状态（batch/status/chunks/model/dimension/错误）
.\.venv\Scripts\python.exe scripts\rag_index.py status

# 给历史 ready 视频补登记索引
.\.venv\Scripts\python.exe scripts\rag_index.py enqueue --all-ready

# 强制重建单个视频索引
.\.venv\Scripts\python.exe scripts\rag_index.py rebuild --video <UUID>

# 没有常驻服务时同步把 pending 跑完
.\.venv\Scripts\python.exe scripts\rag_index.py build --watch 240
```

索引开关：`.env.local` 的 `RAG_INDEXING_ENABLED` 显式优先；未设置时，只要向量接口配好就默认开启。
检索模式：`RAG_RETRIEVAL_MODE=hybrid`（默认）或 `bm25`（用于基线对照）。索引未就绪或向量接口故障会自动退回
`bm25_fallback`，并在问答记录的 `retrieval_mode` 里如实标注。

## 五、专业术语纠正

ASR 会把课程里的术语听错（`SQLite → SaoCAT`、`索引 → 锁印`、`单机 → 单经`、`部署 → 部属` 等）。
术语表在 `backend/app/glossary.py`，转写落库前统一纠正，避免污染检索与回答。

```powershell
# 先看会改多少处
.\.venv\Scripts\python.exe scripts\repair_terms.py --all --dry-run
# 实际修正，并重建章节与索引
.\.venv\Scripts\python.exe scripts\repair_terms.py --all
```

新增错形前请先确认它不是正常用词；脚本按「长词优先」替换，避免短词先吃掉长词。

## 六、验收与排障

```powershell
# 25 题链路验证（状态与引用；人工语义判题另做，口令交互或 ACCEPTANCE_PASSWORD）
.\.venv\Scripts\python.exe scripts\run_acceptance_25.py
.\.venv\Scripts\python.exe scripts\run_acceptance_25.py --reuse      # 复用已上传样本

# 全链路冒烟（保留他人数据，只删自己上传的那条）
.\.venv\Scripts\python.exe scripts\e2e_smoke.py

# 生成 A/B/C 样本（百炼 CosyVoice）
.\.venv\Scripts\python.exe scripts\make_tts_samples.py
```

常见问题：

| 现象 | 排查 |
| --- | --- |
| 上传后立刻 `TRANSCRIBE_FAILED` | 服务刚启动时预热占锁；已改为等锁（`TRANSCRIBE_LOCK_WAIT_SECONDS`，默认 180 秒） |
| 问答全部 `not_found` | 先确认视频内容与问题是否同一门课；再查 `rag_index.py status` 与 `retrieval_mode` |
| 索引一直 `pending` | 索引线程未启动（看 `/api/health.rag_status`）或向量密钥缺失，日志会写明 `EMBED_NOT_CONFIGURED` |
| 端口被占 | 停服脚本核验端口、绝对后端路径和实例，再检查视频/RAG/问答忙状态；其他项目进程保持不动 |
| 本地调用接口被代理劫持 | 本机存在 `http_proxy` 时，脚本需 `trust_env=False`（验收脚本已内置） |
