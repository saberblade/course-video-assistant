## 在这台电脑重启

在仓库根目录打开两个 PowerShell 终端。环境已在本机准备好，保留现有 `.env.local` 即可。

交付检查时已将两项服务启动到后台；端口正在运行时直接打开页面，不要重复启动。本机辅助启动脚本为 `tools/start_integration.ps1`，进程信息在 `logs/integration-services.json`，服务日志为 `logs/integration-*.stdout.log` 和 `logs/integration-*.stderr.log`。以下命令适用于服务停止后的手动启动。

终端一启动后端和同源页面：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --workers 1
```

直接打开 `http://127.0.0.1:8000/screen?view=library` 可以使用构建版。继续开发时，在终端二运行：

```powershell
npm.cmd --prefix frontend run dev -- --host 127.0.0.1
```

开发页面为 `http://127.0.0.1:5173/screen?view=library`，使用本机 `frontend/.env.local` 中的 `VITE_USE_MOCK=false`。前端源码变更后，用 `npm.cmd --prefix frontend run build` 更新 8000 端口提供的构建版。

根目录 `.env.local` 的媒体路径已设置为 `./tools/ffmpeg/ffmpeg.exe` 与 `./tools/ffmpeg/ffprobe.exe`。本机当前已有可用的服务端模型配置，生成式回答已补测连通。其他设备需由后端同学配置实际 `LLM_BASE_URL`、`LLM_API_KEY` 与 `LLM_MODEL` 后启动，正式质量仍按团队题集验收。密钥不写入前端或联调记录。

本次浏览器脚本保存在本机 `tools/integration_browser.cjs` 与 `tools/integration_delete.cjs`，依赖本机 Playwright 路径，按工具目录规则忽略；前者以初始空列表为起点，复跑时应改用独立数据目录，避免与保留样本混淆。
