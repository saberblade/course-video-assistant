## 页面结构

首版只做两个主页面。首页为视频列表与上传区，详情页同时展示播放器、章节提要与问答。首页不设置登录，演示环境不向公共网络开放。

```text
首页
  标题：课程视频复习助手
  简短说明：上传中文课程视频，按原文查找知识点
  上传：选择文件 / 文件限制 / 开始处理
  列表：标题 / 时长 / 创建时间 / 当前阶段 / 打开 / 删除

详情页
  返回列表 / 视频标题 / 当前模式
  左侧：视频播放器 + 原文转写（可折叠）
  右侧上部：章节提要 + 时间点
  右侧下部：问题输入 + 回答 + 引用原文与时间点
  错误区域：原因 + 当前可执行的操作
```

布局示意只规定信息关系，不规定最终像素。优先适配目标电脑的1366×768及以上屏幕。低于该宽度时上下排列，播放器不横向溢出，长引用自动换行。所有操作有可读文字标签和键盘焦点，不只依赖颜色表达状态。

## 交互状态

| 场景 | 页面行为 | 可操作内容 |
| --- | --- | --- |
| 无视频 | 展示用途与输入限制，不展示虚构示例结果 | 选择文件 |
| 文件选择后 | 显示文件名和大小，客户端初筛；服务端仍做最终验证 | 开始上传、重新选择 |
| 上传传输中 | 可显示真实上传字节百分比，文字注明仅上传进度 | 等待；不重复创建任务 |
| queued | 显示排队与耗时，不显示处理百分比 | 返回列表、刷新 |
| transcribing/indexing | 说明当前阶段，保留播放器不可用提示 | 返回列表、刷新 |
| ready | 加载播放器、提要、原文和问题输入 | 提问、点引用、删除 |
| failed | 显示面向用户的错误原因；详细堆栈不出现在页面 | retryable=true时重试，或删除后换文件 |
| 提问等待 | 禁用提交按钮，保留问题文本；最多等待25秒外部调用窗口 | 不重复提交 |
| answered | 显示回答与证据，提示核对原文 | 点击引用，重新提问 |
| not_found | 显示未找到足够依据，引用为空 | 改写问题或查看章节 |
| degraded | 明示原文检索模式，仅显示真实命中片段 | 点击原文定位，稍后重试生成 |

上传阶段的网络失败不能自动无限重发POST，避免生成重复任务。接收202后读取视频对象的id字段，将其作为后续路径中的video_id轮询GET详情，建议每2秒一次；离开页面或ready/failed后停止轮询。用户返回时重新查询状态，不依靠浏览器内存判断。

## 关键细节

点击时间点后设置video.currentTime=start_sec并暂停，显示“已定位至mm:ss，点击播放继续”。loadedmetadata未完成时暂存跳转请求，加载后执行。源视频URL固定走后端content接口，支持Range；禁止把系统文件路径直接暴露给页面。

删除先二次确认“删除该视频及其转写、提要和问答记录？”，成功后退出详情页并刷新列表。queued/transcribing/indexing不显示删除按钮；后端仍检查状态防止竞态。前端把所有模型回答按纯文本或安全转义文本展示，不直接插入原始HTML。

问答是当前视频内的单轮请求。首版只显示当前页面会话内的问答，刷新后不恢复历史列表，不新增历史读取接口。后端持久化问答仅供验收与排查，不用历史回答作为新问题证据。

## 访谈方案

PM邀请3至5位使用录课复习的同学，约10分钟/人。先询问最近一次查找课程内容的实际经历，再展示原型。不要先告诉对方“AI可以节省时间”来诱导回答。

访谈问题：最近一次找知识点是什么时候；当时用什么方法找；大概找了多久；最后有没有找到；遇到不准确的摘要会如何核对；更看重摘要、问答还是直接定位；什么情况下不愿上传视频。记录用户原话、具体行为、需求假设是否得到支持和相应改动。

| 访谈记录项 | 待执行时填写的内容 |
| --- | --- |
| 受访者 | 匿名编号、课程使用习惯、同意参与情况 |
| 实际经历 | 最近一次任务、使用工具、具体卡点 |
| 证据 | 原话或观察记录，不用推测代替 |
| 决策 | 保留/调整/不采纳，以及原因 |

课程原型使用 5 个模拟角色和 10 条配对情景记录完成此项交付。模拟访谈、痛点计数和用时见[调研报告](05_模拟用户调研与需求验证.md)。下面的实地任务方法可用于后续真实用户研究。

## 使用效果验证

可邀请5位同学，各完成两组难度相近的查找任务。半数先用原播放器，半数先用助手，采用不同知识点以减少记忆影响。记录完成情况、定位是否正确、耗时与主观反馈。报告样本量、原始时间、中位数变化和失败任务；不删除失败样本。

这项小样本观察用于发现交互问题，不是必须达标的发布门槛。不预先填写“效率提升百分之多少”。若未实施，验收与项目记录中直接说明尚未验证效率提升。


## 已定稿的细节

初次排队等待按created_at计算；重试保留原created_at，因此重试排队按本次受理时的updated_at计算，均标“已排队”。开始处理后使用elapsed_sec标“已处理”。queued状态elapsed_sec为0不代表没有等待。性能统计使用started_at至finished_at，上传、排队和总等待另报。

章节按视频起点每60秒分窗。标题固定“mm:ss 章节提要”。每窗按时间顺序选取前若干完整转写原句，合计最多120字；单句超过120字时截断并标省略，点击展开完整来源。保留全部segment_ids及来源全文。没有有效转写的窗口跳过，不编造静音章节或知识结论。

| 错误 | 用户文案与动作 | 是否提供重试 |
| --- | --- | --- |
| NO_SPEECH | 未识别到有效讲课语音，请更换清晰中文视频 | 否，换文件 |
| PROCESS_INTERRUPTED | 上次处理因服务中断停止，可重新处理 | 是 |
| TASK_TIMEOUT | 处理超时，建议换短视频，也可重新处理 | 是，用户主动 |
| MODEL_NOT_FOUND | 转写服务尚未准备好，请联系系统工程师 | SYS修复后再试 |
| TRANSCRIBE_FAILED | 转写失败，请提供问题编号给系统工程师排查 | SYS排查后再试 |
| LLM_TIMEOUT或上游故障 | 当前仅展示原文检索结果，未生成综合回答 | 可稍后重新提问，不重建视频 |

真实协议以Video.error.retryable为准。当前原型提供评审状态切换，帮助FE和QA核对分支；原型中的模拟行为不能作为开发完成或测试通过证据。
