# 需求依据与竞品取舍

版本V1.1 定稿。负责人PM。核查日期：2026年11月5日。类型：基于公开官方资料的桌面调研，不冒充真人访谈或实际付费试用。

## 产品结论

本轮确定服务“回看中文录课、找知识点”的大学生，只做单个本地课程视频的复习流程。产品重点是从回答回到课程原文和时间位置。这个方向已有类似产品能力作为可行性参考，但“本校学生愿意使用、能够节省多少时间”仍是待真人任务测试验证的假设。

## 同类产品事实与设计借鉴

| 参考产品 | 官方资料明确描述的能力 | 对本项目的设计影响 |
| --- | --- | --- |
| NotebookLM的音频与YouTube来源能力 | Google官方介绍支持音频文件、公开YouTube链接，并可依据视频转写探索内容、通过引用核对来源 | 借鉴基于来源回答的方式；首版聚焦单个本地MP4及时间点回看，不承担通用资料工作台范围 |
| 飞书智能纪要与妙记 | 飞书官方说明可通过视频会议、录音或上传音视频生成智能纪要，妙记用于查看会议录制内容 | 音视频处理与总结已有成熟应用场景；本项目选择个人课程复习，不复制会议协作、待办分发或组织权限 |
| Clipchamp自动字幕 | Microsoft官方说明可以生成字幕与可编辑转写，并通过转写中的时间点定位视频 | 把原文与时间点作为核心交互；首版不做视频剪辑或字幕编辑，资源用于问答与引用验证 |

以上仅描述官方列明的功能，不据此断言某产品缺少某能力，也不声明本项目首创。没有开展竞品性能、价格或用户规模比较，不提供虚构的优势评分。

## 已完成的产品取舍

| 决策 | 为什么这样定 | 开发与验收影响 |
| --- | --- | --- |
| 中文讲课音轨作为唯一知识来源 | 与五天和本地设备边界匹配 | 不回答仅出现在画面中的图表；界面明确音轨能力 |
| 首版单视频、单轮问答 | 避免检索范围与对话记忆混淆 | 问题必须自足，禁止跨视频证据和新增历史接口 |
| 回答必须带真实片段来源 | 流畅文字不足以让用户核对课程 | BE校验ID与秒数，QA另做语义支持核验 |
| 摘要先做提取式章节提要 | 降低自由生成摘要的无依据内容与调用成本 | 约60秒一窗、展示上限120字、能展开完整来源 |
| 无依据拒答与接口降级分开 | 课程没讲和服务暂不可用需要不同动作 | not_found无引用；degraded明示原文检索 |
| 先不做账号与多人隔离 | 单机复习原型和本地工程便于五人交付 | 固定本机运行，不把它宣传为公网产品 |
| 导出、翻译、OCR、多轮、自动出题延期 | 当前核心流程需要充分联调和验收 | 本轮不为这些功能分配研发任务 |

## 用户假设及验证安排

H1：学生曾因不记得视频位置而反复拖动进度条。H2：能查看原文与时间点比只看到生成答案更便于核对。H3：术语检索和章节提要能够缩短部分查找任务时间。当前三项都没有实地证据。

PM 已完成课程原型的模拟访谈与配对任务。结论按模拟样本解释，并对应到 R01 至 R10 的产品取舍。访谈方案和独立验证方法随资料归档。[模拟用户调研](05_模拟用户调研与需求验证.md) · [任务研究方法](02_页面交互与需求调研.md)
