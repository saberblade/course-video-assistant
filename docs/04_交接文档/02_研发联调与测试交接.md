# 研发联调与测试交接

版本：V1.1。协调人：PM。技术主责：FE、BE、SYS；独立验证：QA。接口与交接规范已备齐；实际代码、运行与成员签收尚未执行。

## 统一规则

交接遵循“交出材料、接收人独立运行、记录结果”三步。演示视频、截图和日志需要标注样本ID、代码版本、环境、日期和执行人。聊天截图或“我这里能跑”不足以说明接收环境可用。

技术细节以`03_技术方案与接口`和[统一约定](../00_项目导航与统一约定.md)为准。所有接口变更先同步FE、BE、QA、SYS，再修改实现。交接确认写入[记录表](../07_管理记录/02_决策与交接确认记录.md)。

## SYS交接BE 音视频与转写模块

计划：M1前给出真实样本试跑和契约，M2前交付可集成模块。

| 交出项 | 必须说明 | 接收检查 |
| --- | --- | --- |
| 环境与依赖 | Python、FFmpeg/ffprobe、faster-whisper的实际版本，small模型本地目录，CPU int8参数 | BE在约定环境独立加载模型，不依赖SYS个人临时目录 |
| 模块与调用契约 | 输入文件路径、输出数据、异常、超时与资源清理，函数签名以技术契约为准 | BE使用技术文档中的调用方式完成成功与失败样例 |
| 媒体校验 | MP4、H.264、AAC、大小、时长、音轨检查及拒绝原因 | 对无音轨、损坏文件、超长文件返回约定错误，不阻塞队列 |
| 转写数据 | 可追溯片段ID、start_sec、end_sec、text，时间从视频起点计秒 | BE与QA抽查原视频，开始小于结束，时间在视频范围内，文本非伪造 |
| 模型试跑证据 | 授权样本ID、模型/参数、预热说明、耗时和转写输出 | QA核对识别质量，BE核对字段可入库 |
| 超时与资源释放 | 任务20分钟上限、子进程结束、临时音频清理和错误日志 | 模拟失败后下一个任务仍能执行，无僵死进程和无限等待 |

**分工边界：** SYS提供音视频处理和模型运行能力；BE负责持久化队列、任务状态、业务数据、索引和接口。BE不能直接把原始模块异常展示给用户，需转为统一错误格式。

**退回条件：** 缺模型文件或依赖；仅在个人电脑某个目录可运行；时间戳失真；没有失败行为；无法停止超时任务；耗时没有真实样本证据。若从small改为base，须有PM/QA决策记录及同一验收集的复测。

## BE交接FE API与业务状态

计划：M1冻结契约，M2前真实服务可用，M3完成稳定版。

BE须提供：

- 环境地址、启动说明、代码版本及接口文档入口。
- 全部约定接口的请求和响应，包括正常与关键错误样例。
- 上传202、删除204、处理中删除409等语义，以及错误结构`{error:{code,message,retryable},request_id}`。
- 五状态及每种状态可做的操作，轮询建议和任务超时表现。
- 真实样本ID、可播放地址、transcript和summary结构、问题接口及三类回答状态。
- Range支持的复现方式，确保播放器按时间跳转时可以继续读取视频。
- UTC记录时间与秒数偏移的说明。不得把毫秒当秒，也不得对视频偏移添加时区。

FE接收时必须执行：上传一段真实样本，检查状态轮询；打开ready视频，播放并跳转；执行一题正题和一题无答案题；模拟API不可用，确认degraded/extractive模式；对failed任务重试；删除ready/failed视频并确认刷新后消失。

**退回条件：** 文档和接口字段不同；只有模拟服务；正常响应额外套了data包装；模型直接输出的时间戳未经验证；接口错误无request_id；秘密出现在浏览器请求或构建文件；Range失败导致跳转不可用。

## FE交接BE和SYS 构建与集成

FE交付生产build目录、源码版本、依赖锁文件、构建说明、路由约定、API地址配置、错误映射与已知问题。前端build由FastAPI同源托管，演示入口为`http://127.0.0.1:8000`；开发时代理配置不得带入错误的生产地址。

BE检查静态资源、页面刷新与`/api`路径不冲突；SYS在目标设备按说明构建或使用对应build产物，并核对版本。浏览器中不得出现模型API密钥、内部异常栈或错误的跨域请求。

**退回条件：** 只能通过开发服务器打开；缺锁文件；前端和后端来自不同不兼容版本；部署后刷新页面404；引用无法跳转；等待态、失败态或降级文案缺失。

## FE与BE共同完成M2纵向流程

使用同一真实样本按以下顺序验证：上传后返回202及视频对象id（后续路径中的video_id）；queued、transcribing、indexing到ready；显示转写与提要；提问得到可核对回答；至少一条有效引用跳转到正确片段；无依据题不编造；失败能解释并可重试。

SYS协助记录模型与运行环境，QA独立操作并记录证据。尚未接入的功能逐项标记，不用演示录像替代真实接口的完成情况。

## 开发交接QA 测试候选版本

计划：M2接收主流程，M3接收完整候选版。FE、BE、SYS分别提交本岗位交付，BE汇总候选版本，SYS提供稳定运行环境。

| 必交材料 | 内容要求 | QA接收检查 |
| --- | --- | --- |
| 候选版标识 | 版本标签或提交ID、构建日期、FE/BE/模型版本 | 本次测试可以定位到同一组代码和配置 |
| 功能清单 | 已实现P0、未实现项、已知问题及影响 | 与PRD逐项对应，未实现项不能从用例中删除 |
| 运行与配置 | 启停方法、端口、模型目录、脱敏配置、数据重置方式 | QA能独立访问，测试失败后可恢复环境 |
| 自测证据 | 主流程、重试、删除、重启、拒答、降级、输入校验 | 有步骤、实际结果、版本和request_id |
| 测试数据 | 授权样本和标注位置，不含真实API密钥 | QA能还原输入，样本来源明确 |
| 限制说明 | 单机、并发、无账号、语音内容范围、性能观察 | 用例和对外展示口径一致 |

**进入测试的条件：** 版本固定、健康检查通过、最小主流程可运行、配置和已知问题完整。若测试过程中热改代码，QA需记录新版本并重测受影响用例。

## QA交接开发 缺陷与回归

缺陷至少包括：编号、标题、严重级别、环境与版本、前置条件、输入样本/问题、复现步骤、期望结果、实际结果、日志request_id或录像、建议主责、当前状态。

- 阻断：服务无法启动、主流程无法继续、结果/引用伪造、密钥泄露、数据破坏。立即通知PM与主责人。
- 严重：P0关键结果错误、无依据题编造、重试/删除/来源回看不可用。M3前修复并回归。
- 一般：不阻断主流程的布局、文案或次要体验问题。PM依据影响安排处理。

开发提交修复版本和影响范围后，QA按原步骤回归，再补受影响的相邻流程。开发自称“已修复”不等于QA已关闭。

## QA交接PM 最终验收建议

计划：M4前。QA提交版本与环境、P0结果、20道正题与5道无答案题逐题证据、引用时间误差、10次问答中位数与最大值、3至5分钟样本处理耗时、阻断/严重缺陷状态、已知限制和结论建议。

20道正题全部计入分母，not_found或degraded都按该正题未通过；另报降级数量。引用误差统计写清实际检查了多少条有效引用；不能把“不含引用的题”静默排除后仍宣称整体回答达标。

PM核对证据后决定通过、附条件接受或整改后复验。指标未达标不能改写为达标；附条件接受须写明限制、用户影响、整改主责与节点，S1/S2未解决不能按通过处理。展示按用户最新要求暂缓，不列入本轮交接。
